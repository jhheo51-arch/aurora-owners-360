# 오로라 오너스 360 확장 설계안 (원문)

> 2026-10-14 사용자 제공 원문을 그대로 보관한다. PRD 반영본은 [PRD.md §16](PRD.md), 버전 배치는 PRD §13.

[목표] 오로라 오너스 360이 Salesforce Automotive Cloud의 기능을 모두 갖추고(라이선스 없이 표준·커스텀 기능으로 구현), 그 위에 차별화 기능과 상담원 업무를 대신하는 Agentforce·AICX를 더한다.

## A. Automotive Cloud 대비 현황과 추가 기능
현황:
| Automotive Cloud 기능 | 오로라 현황 | 조치 |
|---|---|---|
| 차량(Vehicle) | 있음 Vehicle__c | 유지 |
| Driver 360(고객 한 화면) | 일부: 차주 페이지에 보유 차량·VOC | v3 차량·고객 타임라인으로 보강 |
| 서비스 케이스 | 있음 Case VOC + Flow | 유지 |
| 보증 상태 | 일부: 만료일 2개(기간만) | 보강 |
| 보상·클레임 | 있음 Compensation__c + v2 승인 | 유지 |
| 리콜 캠페인 | 일부: v5에 표준 Campaign 계획 | 차량 단위로 재설계 |
| 리드·판매 기회 | 일부: v5 계획 | 구체화 |

추가 기능:
- 차량 모델 카탈로그: Vehicle_Model__c(차종·트림·배터리 용량·출시가·보증 정책), 차량이 모델을 참조
- 차량-사람 관계: Vehicle_Party__c(소유자/주 운전자/리스 이용자/이전 소유자, 시작·종료일), 소유권 이전 이력
- 가구·법인: Account 레코드 유형(가구 / 법인 Fleet)
- 딜러·서비스센터: Account 레코드 유형 "딜러/서비스센터"로 Service_Center__c 선택 목록 대체, 센터별 VOC·대기 현황
- 정비 이력·예약: Service_Visit__c(입고일, 주행거리, 정비 항목, 보증 적용, 비용, 센터), VOC 연결
- 보증 고도화: Vehicle_Warranty__c(일반/파워트레인/배터리/연장 × 기간+주행거리 중 먼저 도달)
- 리콜 캠페인: Recall_Campaign__c + Recall_Vehicle__c(통지·입고·조치 완료), 이행률
- 판매: Lead(시승 신청) → Opportunity(구매·관심 차종) → 딜러 배정
- 금융·리스: Finance_Contract__c(할부/리스, 만기일 → 재구매 상담 자동 생성)
- 커넥티드카: Vehicle_Signal__c(배터리 경고·충전 오류 이벤트, 스크립트로 시뮬레이션), 심각 신호 → VOC 자동 생성
- 표준 Asset·WarrantyTerm 등은 Field Service 의존 가능성이 있어 재현성을 위해 커스텀 오브젝트 우선(사용 가능 여부 확인)

## B. 고장·부품 지식 위키 + 차량 이력 + 유사 사례
데이터 구조:
  Part__c(부품 카탈로그): 부품번호, 이름, 계통(배터리/구동/제동/공조/전장/차체), 부위, 적용 차종, 보증 구분, 3D 부위 ID
  Failure_Mode__c(고장 위키 문서): 증상, 원인, 진단 절차, 해결 단계, 적용 차종, 관련 부품, 심각도, 자가 해결 가능, 성공·실패 횟수, 상태(초안/검토/게시), 버전
  Case_Part__c: VOC ↔ 교체·점검 부품 연결
  Case.Failure_Mode__c: VOC ↔ 고장 위키 연결
  Vehicle__c 차량 타임라인: VOC + 정비 + 리콜 + 교체 부품
지식이 쌓이는 흐름:
  1. VOC 종결 시 고장 유형 선택 또는 "새 고장 유형 제안"(유효성 규칙으로 필수)
  2. 새 유형이면 AI가 VOC 내용으로 위키 초안 작성
  3. 품질·안전 대응(연태오)이 검토 후 게시 — 사람이 검증한 문서만 자동 해결에 사용
  4. 해결될 때마다 성공 횟수 누적, 실패가 많으면 재검토 대상
유사 사례 추천(VOC 화면 상위 3건, 규칙 기반 Flow/Apex로 먼저 구현):
  같은 차량(VIN)의 이전 VOC(가장 높음, 반복 결함·레몬법 신호) > 같은 차종+같은 부품/계통 > 같은 VOC 유형+증상 키워드 > 성공 횟수 많은 위키 가산점
  의미 기반 검색(RAG·벡터)은 Data Cloud 제약이 있어 나중 단계
Salesforce Knowledge: 버전·게시 흐름은 좋지만 org 전역 설정과 3D 연결 문제로, 커스텀 오브젝트 위키를 먼저 만들고 긴 문서만 Knowledge로 확장 검토

## C. 직원용 Agent "오로라 케어 코파일럿" (상담원 업무를 실제로 대신)
위치: VOC 레코드 화면·오로라 홈의 Agentforce 패널. 지금 보고 있는 레코드("이 VOC")를 알고 대화.
토픽과 액션:
| # | 토픽 | 상담원 발화 예 | Agent 동작 | 구현 |
|---|---|---|---|---|
| 1 | VOC 요약 | "이 VOC 정리해 줘" | 차주·차량·보증·이관·보상 이력 3줄 요약 | Prompt Template(Case) |
| 2 | 차주 답변 초안 | "고객한테 보낼 답변 써 줘" | 보증 여부·조치 내용 반영 안내문 | Prompt Template |
| 3 | 업무 조회 | "내 진행 중 VOC 중 기한 임박한 거?" | 기한 순 목록 | Flow 액션(조회) |
| 4 | 보증 확인 | "VEH-0003 배터리 보증 남았어?" | 일반·배터리 보증 만료일과 남은 기간 | Flow 액션 |
| 5 | 보상 추천·등록 | "이 건 보상 뭐가 맞아?" → "대차 지원 40만 원 등록해 줘" | 유형·보증 기준 추천, 확인 후 '요청' 상태로 등록, 필요한 승인 단계 안내 | Flow 액션(생성) |
| 6 | 팀장 이관 요청 | "정원이 팀장한테 넘겨 줘, 사유는 …" | 팀장 도움 필요+사유 저장 → v1 Flow가 이관 | Flow 액션(수정) |
| 7 | 대화형 VOC 접수 | "윤하겸 고객 노스라이트 원격 공조 안 된대" | 차주·차량 찾기, 유형 분류, VOC 생성(기한 자동) | Flow 액션(생성, v2 빠른 VOC 접수 재사용) |
| 8 | 안전 결함 대응 안내 | "브레이크 경고등이래" | 안전 결함 분류, 즉시 이관, 연태오 공유·대차 검토 절차 안내 | 토픽 지침 + 액션 6·7 |
| 9 | 유사 사례·위키 | "비슷한 사례 있어?" | B의 유사 사례 상위 3건과 해결 단계 | Flow 액션 |
| 10 | 레몬법·반복 결함 확인 | "이 차 레몬법 대상이야?" | 정비 이력 기준 판정 결과와 근거 | Flow 액션 |
가드레일:
- 승인·종결은 사람만. Agent는 보상을 '요청' 상태로만 생성, 승인·반려는 v2 승인 화면에서 사람이 처리
- 기록을 바꾸는 작업은 항상 확인 후 실행("등록할까요?" → "예")
- 안전 결함은 무조건 이관, Agent가 낮추지 않음
- v1 Flow·v2 유효성 규칙이 Agent가 만든 데이터에도 똑같이 적용(사람과 AI가 같은 통제)
구현 구성(실습 org에서 써 본 방식과 동일):
- Prompt Template: VOC 요약, 차주 답변 초안, 상담사 인계 요약, 해결법 고객 안내문, 위키 초안
- 액션용 자동 Flow: 조회, 보증 확인, 보상 등록, 이관 요청, VOC 접수, 유사 사례, 레몬법 판정(입출력 변수 구성)
- Agent 정의: 실습 Agent AI_Sales_Assistant처럼 Agent Script(AiAuthoringBundle)
- 권한: Agent 사용 권한을 Aurora_Owners_360_User 권한 세트에 추가
주의: Agentforce는 org 전역 설정 필요(실습 때 켜져 있을 가능성, 변경 필요 시 먼저 확인), "Agentforce가 켜진 DE"에서만 재현됨을 PRD에 명시, DE AI 요청 한도가 있어 테스트는 짧게

## D. AICX — 고객용 AI 상담 + 사람 연결
흐름: 차주 문의 → ① 고객 식별(전화·이메일 → 차주+보유 차량) → ② 맥락 분석(VOC 이력·등급·보증·위험 신호)
  → 즉시 상담사 연결 조건이면 상담사 연결(AI 요약·이미 시도한 방법 인계)
  → 일반 문의면 해결 이력(B 위키) 검색 → 해결법 있으면 AI 단계별 안내 → "해결됐나요?" 예: VOC 자동 생성·종결("AI 자가 해결")+만족도 / 아니오: 상담사 연결
  → 해결법 없으면 VOC 접수(기한 자동)+상담사 배정
즉시 상담사 연결 규칙(AI 판단이 아니라 Flow 규칙, 이관 사유 기록):
  안전 결함 키워드(브레이크·화재·연기·경고등) / 최근 90일 VOC 2건 이상 또는 같은 차량·유형 재발 / 과거 이관·기한 위반·보상 반려 이력 / 플래티넘 등급 / 레몬법 후보 / 강한 불만 표현(환불·소송·언론)
배정: 충전·배터리 → 도하람(EV 기술), 안전 결함 → 정원이(팀장)+연태오 공유, 기존 담당 상담원이 있으면 그 사람
자동 해결 허용 범위: 커넥티드카 앱·충전 사용법·출고 일정 조회 등 저위험만. 안전 결함·보상 요구·입고 필요 하자는 자동 해결 금지
피드백 루프: AI 자가 해결 VOC 자동 생성·종결, 해결법 실패 누적 시 자동 안내에서 제외, 상담원이 종결 때 남긴 해결 정보가 다음 고객의 자동 해결 자료가 됨
필요한 필드: Case(원인, 해결 방법, 해결 방식, 자가 해결 가능, 접수경로 "AI 상담", AI 처리 결과, 이관 신호, 만족도), Contact(고객 위험 점수, 최근 90일 VOC 수)
고객용 Agent "오로라 AI 상담": 실제 웹·앱 채팅 채널은 DE 제약이 커서 처음엔 Agent Builder 미리보기에서 차주 역할 시연, 채널 연결은 확인 후
상담 직원은 Salesforce 사용자가 아니므로 Omni-Channel 대신 VOC 생성+담당 배정+이관 목록으로 연결 표현
시연 시나리오(현재 샘플 데이터): 다른 노스라이트 차주 "원격 공조 안 돼요" → VOC-B 해결법 자동 안내 / 한서아(플래티넘, 안전 결함 이력, 같은 차량 VOC 2건) → AI가 답하지 않고 바로 상담사 연결
모델: 구현은 Claude Code, 실행은 Agentforce 기본 모델. LLM은 요약·안내문·위키 초안에만 쓰고 판단(이관·승인)은 규칙. Prompt Builder에서 Claude 모델 선택 가능 여부는 org에서 확인
지표: AI 자가 해결률, 상담사 연결률(사유별), 재문의율, 해결법별 성공률, 상담사 처리 시간

## E. 시각화
대시보드: 기한 준수율, 유형·차종별 VOC, 부품별 고장 TOP, 보상 비용, AI 자가 해결률
차량 3D 컴포넌트(LWC + Three.js 정적 리소스):
  차량 3D 뷰(회전·확대, 세단/SUV/소형) / 분해도(배터리·모터·제동·공조·차체가 벌어지며 분리) / 이상 부위 포인트(VOC에서 열면 해당 부품 빨간 하이라이트+핀, 예: VOC-C → 제동 계통) / 고장 히트맵(차종별 부품 VOC 건수 색 농도, 리콜 조기 경보 연결) / 부품 클릭 시 관련 위키·같은 부품 VOC·교체 이력
  연결: Part__c.3D 부위 ID ↔ 모델 부품 이름. VOC → 교체·의심 부품 → 3D 부위 ID → 하이라이트
  주의: 실제 차량 CAD·출처 불명 모델 금지 → Three.js 기본 도형으로 만든 가상 오로라 차량(로우폴리) 권장. 정적 리소스 크기 제한 고려. 대안으로 2D SVG 도면을 먼저 만들고 3D로 확장 가능. Salesforce 반영 전 HTML 프로토타입으로 모양 확정 가능

## F. 차별화 (Automotive Cloud에도 없는 것)
- 한국 레몬법 자동 감지: 인도 후 1년·2만km 이내 같은 하자 반복(중대 하자 2회·일반 하자 3회 수리 후 재발) → "교환·환불 대상 가능" 플래그 (기준 수치는 법령으로 재확인)
- 리콜 조기 경보: 같은 모델·같은 유형 안전 결함 VOC가 N건 이상이면 연태오에게 경보 (§14 세타2·BMW·Toyota 실패 사례 대응)
- EV 배터리 건강도(SOH): 점검 시 SOH(%) 기록, 보증 기준(예: 70%) 미달 시 배터리 보증 클레임 대상 표시
- 고객 건강 점수(이탈 위험), 종결 후 CSAT 설문, 서비스센터 용량·대기 관리
- 사람과 AI가 같은 규칙(Flow·유효성 규칙)으로 통제되는 Agent 가드레일 구조
