## F1. 알림 (Custom Notification + 모바일 push)
**원칙**: 직원 10명은 `Care_Staff__c` 레코드라 Salesforce 사용자가 아니다(DE 라이선스 2개). 알림은 **로그인 사용자(관리자)에게** 보내고 문구에 **대상 직원**을 적는다. 실제 회사라면 수신자를 `Care_Staff__c.User__c`로 바꾸면 되도록 수신자 결정을 한 메서드에 모은다.

| 코드 | 상황 | 시점 | 문구 예 | 클릭 시 |
|---|---|---|---|---|
| N1 | 안전 결함 팀장 이관 | VOC 저장 시 `Escalation_Status__c`='요청'으로 바뀜 | "[안전] 팀장 정원이님께 이관: VOC 00001041 주행 중 브레이크 경고등" | VOC |
| N2 | 보상 승인 요청 | 보상 저장 시 승인 필요(`Approval_Level__c` 팀장/센터장) + 상태 '요청' | "[승인 요청] 센터장 육지안님: CMP-0007 120만 원" | 보상 |
| N3 | 응답 기한 임박·초과 | **예약 Flow** 매시간: 첫 응답 없음 AND 기한 1시간 이내/초과 | "[기한 임박] 미나미님 VOC 00001033, 40분 남음" | VOC |
| N4 | AI 상담 상담사 연결 | AICX가 VOC 생성(`AI_Outcome__c`='상담사 연결') | "[AI 상담 연결] 김가영님: 남궁린 고객 — 강한 불만(환불)" | VOC |
| (기존) | 리콜 조기 경보 | 그대로 | | 리콜 경보 |

- 구성: `CustomNotificationType` `Aurora_Work_Alert` 1개(desktop·mobile), Apex `AuroraNotifier.send(code, targetId, title, body)`(수신자 결정·중복 방지), N1·N2·N4는 기존 트리거/서비스에서 호출, N3은 예약 Flow `Aurora_SLA_Reminder` → Apex 호출.
- 중복 방지: 같은 레코드·같은 코드는 1회만(N3은 '임박'과 '초과' 각 1회) — Case에 `Last_Alert_Code__c`(텍스트) 기록.
- **모바일 push**: Salesforce 모바일 앱에 같은 사용자로 로그인하면 별도 설정 없이 push로 받음(알림 유형 `mobile=true`). 시연은 데스크톱 벨 + 휴대폰 스크린샷.
- 기존 v1 Flow·v4 리콜 경보 동작은 바꾸지 않는다.

## F2. '차주·차량' 통합 탭
- Lightning 앱 페이지 `Aurora_Owners_Vehicles` + 탭 "차주·차량"(오로라 앱만). 앱 탭 순서: 홈 · **차주·차량** · 사례 · 보상·조치 · 상담 직원 · 정비 이력 · 고장 위키 · 리콜 경보 · AI 상담. 기존 '고객 차량'·'연락처' 탭은 **오로라 앱 탭 목록에서만 뺀다**(오브젝트·레코드 페이지·리스트 뷰 유지, 새싹 앱 무변화).
- LWC `auroraOwnerVehicleBoard`(Apex `AuroraOwnerBoardController`, 오로라 차주만 = 연락처 이메일 `@aurora.example.com` 또는 `Vehicle_Party__c` 있음):
  - 위: 검색(이름·전화·번호판·VEH 번호) + 필터 칩(위험 높음 / 레몬법 주의 이상 / 진행 중 VOC 있음 / 보증 만료 임박)
  - 목록 행 = 차주: 이름·등급·위험 배지·진행 중 VOC 수 → **펼치면 보유 차량 카드**(번호판·모델·주행거리·보증 게이지 요약·레몬법·반복 결함) + 진행 중 VOC 링크
  - 차주 이름 → 차주 페이지, 차량 카드 → 차량 페이지, [새 VOC] → 빠른 VOC 접수(차주·차량 미리 채움)
- 상태는 색 + 기호 + 글자(v3.5 원칙).
- 주의(함정 16): 오로라 앱은 탐색 개인 설정이 켜져 있어 **사용자가 연필 → '원래대로 재설정'** 해야 새 탭 구성이 보인다.

## F4. 유사 사례·고장 이력 RAG (Apex 검색 기반)
**구조**: Retrieve(Apex) → Augment(Prompt 병합) → Generate(Claude) → 출처 표시.

1. **검색 `AuroraRagRetriever`**(Apex): 질의 = VOC 제목·설명·유형·차량 모델·계통. 후보 = 종결 VOC(`Resolution__c`·`Root_Cause__c`·`Resolution_Method__c` 있음) + 게시된 고장 위키 + 같은 모델 정비 이력(하자 수리). 점수 = 기존 `SimilarCaseService` 키워드 점수 + 같은 모델 +2 + 같은 계통 +2 + 최근 1년 +1. 상위 **5건**을 근거 블록으로.
2. **근거 블록 형식**(Prompt에 들어가는 텍스트):
   `[근거1] VOC 00001021 · 노스라이트 · 충전 · 원인: 충전 모듈 펌웨어 · 조치: 펌웨어 업데이트 · 결과: 재발 없음`
   `[근거2] 고장 위키 FM-003 급속 충전 속도 저하 · 단계: …`
3. **Prompt Template**: 새 `Aurora_RAG_Answer`(§19-5 틀) — 입력 = VOC + Apex 근거 블록(Apex 병합 필드 / Flex 템플릿). 규칙: **근거에 없는 내용 금지**, 문장마다 `[근거n]` 표시, 근거가 2건 미만이면 "비슷한 해결 사례가 부족합니다" + 사람 확인 권고.
4. **사용처**:
   - VOC Care Assistant 새 액션 "비슷한 고장 해결법 알려 줘"(`AuroraRagAnswerAction`) — 기존 유사 사례 액션은 목록, 새 액션은 근거 기반 답변
   - VOC 화면 `auroraSimilarCases`에 [AI 해결 가이드] 버튼(답변 + 근거 링크)
   - v4.3 AI 상담: 고장 문의에서 위키 매칭이 없을 때 RAG 답변을 **상담원 인계 메모**로만 사용(고객에게 직접 노출 안 함 — 판단·약속은 사람)
5. **평가**: 근거 정확도 테스트 5건(정답 VOC가 상위 5에 들어오는지 Apex 테스트), 근거 없는 질문에서 "부족" 응답 확인.
- 벡터 검색(Data Cloud·Agentforce Data Library)은 **로드맵**: DE 재현이 불확실해서. 검색기 인터페이스를 분리해 나중에 교체 가능하게.
